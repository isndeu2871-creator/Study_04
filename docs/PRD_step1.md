# PRD 1단계 — 냉장고 사진에서 식재료 인식

## 목표

사용자가 올린 냉장고 사진을 이미지 모델에 보내 식재료 목록을 뽑아내고,
사용자가 그 목록을 손으로 고칠 수 있게 한다.

## 구현 방식

- 화면: Streamlit
- 배포: Streamlit Community Cloud
- 키: 내 PC 에서는 `.env`, 배포 뒤에는 Streamlit `Secrets`

노트 6.4.5.1목에서 Streamlit, Flask, React+FastAPI 를 견준 뒤 "무료이면서 설정이 가장 적은"
기준으로 Streamlit 을 골랐다.

## 쓰는 모델

| 차례 | 모델 |
| --- | --- |
| 1 | `google/gemma-4-26b-a4b-it:free` (수업 선정) |
| 예비 1 | `minimax/minimax-m3.1-flash:free` |

| 예비 3 | `dots-studio/dots-3-note-preview:free` |

예비는 서로 다른 제공 업체로 섞는다. 같은 업체는 함께 막히기 때문이다.

## 기능

### F1. 사진 올리기

- 파일 고르기와 끌어 놓기 둘 다 받는다
- 받는 형식: JPG, PNG
- 올린 사진을 화면에 보여 준다

### F2. 사진 줄이기

- 긴 변이 1024px 을 넘으면 1024px 로 줄인다
- JPEG 품질 85 로 다시 압축한다
- 줄이기 전후 용량을 화면에 보여 준다

용량을 줄이지 않으면 요청이 느려지고 토큰이 많이 든다.

### F3. 식재료 인식

- 줄인 사진을 base64 로 바꿔 이미지 모델에 보낸다
- 모델에게 JSON 으로만 답하게 한다

```json
{"ingredients": [{"name": "달걀", "quantity": 3, "unit": "개", "category": "유제품/계란"}]}
```

- 분류는 `채소`, `과일`, `육류`, `해산물`, `유제품/계란`, `조미료`, `음료`, `기타`

### F4. 시도와 전환

1. 선정 모델로 1차 시도
2. 429 면 10초 뒤 2차 시도, 다시 20초 뒤 3차 시도
3. 그래도 막히면 예비 모델로 넘어간다
4. 404 면 재시도 없이 바로 예비 모델로 넘어간다

응답이 HTTP 200 이어도 `choices` 가 비어 있을 수 있다. 이때 앱이 죽지 않게 한다
(노트 6.4.5.3목 c.2 의 KeyError).

### F5. 결과 고치기

- 재료마다 한 줄에 `이름`, `수량`, `단위`, `삭제` 를 둔다
- 단위는 드롭다운: `개`, `병`, `봉지`, `팩`, `단`, `g`, `kg`, `ml`, `L`, `기타`
- 재료를 손으로 더할 수 있다
- 목록 위에 `AI 인식 결과는 부정확할 수 있습니다` 를 적는다

### F6. 실패를 정직하게 알리기

- 인식에 실패하면 이전 결과를 지우고 실패했다고 화면에 적는다
- 몇 차 시도였는지, 어느 모델이었는지, 무슨 오류였는지 적는다

성공한 옛 결과가 남아 이번 사진의 결과처럼 보이면 안 된다.

## 받아들이는 조건

- [ ] 5MB 사진을 올려 200KB 아래로 줄인다
- [ ] 재료 목록이 이름, 수량, 단위, 분류와 함께 나온다
- [ ] 선정 모델이 429 면 예비 모델로 넘어가 결과가 나온다
- [ ] 빈 응답이 와도 앱이 죽지 않는다
- [ ] 실패하면 실패했다고 화면에 뜬다
- [ ] 폭 375px 에서도 한 줄 배열이 깨지지 않는다
